## B. 부분 대응 — 시안 1화면 ↔ 우리 여러 화면 (7묶음 / 우리 14화면)

시안 한 화면이 우리 여러 화면으로 쪼개져 있거나, 기능이 더 붙어 있습니다.
**시안 레이아웃을 기준 화면에 적용하고, 넘치는 기능은 2차 인터랙션으로.**

| 시안 | 우리 화면 | 처리 방향 |
|---|---|---|
| `store-sync` | `StoreSearch` · `StoreManual` · `StoreConfirm` | 시안은 1화면(연동 버튼+직접입력). 우리 3단계 흐름은 유지하되 각 화면에 시안 폼·버튼 패턴 적용 |
| `permissions` | `Terms` · `PermissionsInfo` | 시안은 약관 체크 + 권한 안내가 한 화면. 우리는 동의(필수)와 안내(참고)를 분리 — 흐름 유지, 시안 체크박스·타일 패턴 적용 |
| `shoot-topic` | `PurposeSelect` · `PromotionDetail` | 시안은 2×2 타일 + 입력. 우리는 목적(4.1)과 상세(4.2)가 별도 API라 분리 필요 — 타일 디자인 이식 |
| `format` | `PlanSummary` | **격차 큼.** 시안=영상+컷목록+버튼. 우리=변환배너+원본+요약카드+**컷별 대사편집**. 대사편집을 **접기/펼치기 또는 바텀시트**로 내리고 기본 화면은 시안 구조로 |
| `choreo` | `TaskGuide`(DANCE) | 시안은 안무 전용 화면(영상+안무 순서 목록). 우리는 guide_type 분기 — DANCE일 때 시안 레이아웃 적용 |
| `editing` | `Render` · `EditResult` | 시안=진행 단계 표시 1화면. 우리는 렌더 진행과 결과·수정요청 분리 — 유지, 시안 진행표시 패턴 적용 |
| `export` | `Outputs` · `Publish` | 시안=미리보기+다운로드/내보내기+음원+**편집 가능한 게시글 제목·본문**. 우리는 문구가 읽기전용 → 편집 가능하게 + 복사 버튼 |
| `terms`/`privacy` | `Legal` · `Terms`(read) | 시안은 본문 화면 2개. 우리는 목록(Legal)→뷰어(Terms read). 유지, 본문 타이포 적용 |
| `states` | — | 리뷰용 카탈로그. 우리는 각 화면에 인라인 처리 중 — **신설하지 않음** |

### 1. `dance-camera` — 시안 PiP vs YouTube 약관

시안 2차 `PipGuide`는 카메라 위에 레퍼런스 영상을 띄우고 **그 위에 재생/확대 버튼을

만들면 *"플레이어 앞에 어떤 요소도 올릴 수 없다"* 는 YouTube 조항에 걸립니다.
(우리가 안무 카메라를 상하 분할로 만든 이유)

**제안**: PiP 자체는 도입하되(카메라가 뒤에 있는 건 무방),
재생·일시정지는 **유튜브 자체 컨트롤**에 맡기고, 확대/축소·닫기 버튼은
**영상 사각형 바깥의 프레임 테두리 영역**에 둡니다.
