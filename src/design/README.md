# 디자인 담당이 보는 문서

> 개발을 몰라도 됩니다. 이 폴더의 **`tokens.json` 하나만** 고치면 앱 전체 색·글자·간격이 바뀝니다.

---

## 1. 건드려도 되는 파일 / 안 되는 파일

| 파일 | 누가 | 설명 |
|---|---|---|
| **`tokens.json`** | 🎨 **디자이너** | 색, 글자 크기, 간격, 둥근 모서리 값. 여기만 고치세요. |
| `theme.ts` | 👨‍💻 개발자 | tokens.json 을 코드가 쓸 수 있게 감싸는 층 |
| `fonts.ts` | 👨‍💻 개발자 | 폰트 로딩 |
| `../components/*` | 👨‍💻 개발자 (디자이너 리뷰) | 버튼·카드 같은 부품. 모양이 바뀌면 여기도 같이 봐야 합니다. |

---

## 2. tokens.json 읽는 법

```json
"brand": {
  "500": "#F0561F",   ← 밝은 브랜드색 (진행바, 강조 아이콘)
  "600": "#D93E12",   ← 버튼 배경 (기본 브랜드색)
  "700": "#AE2F0B"    ← 눌렀을 때 / 텍스트로 쓸 때
}
```

숫자가 클수록 어둡습니다. 이 규칙은 `ink`(회색 계열)도 똑같습니다.

### 색을 바꿀 때 반드시 확인할 것

브랜드색을 흰 글씨 버튼 배경으로 씁니다. **대비가 4.5:1 이상**이어야 합니다.
현재 `#D93E12` + 흰 글씨 = 약 4.8:1 로 통과합니다.
더 밝은 색으로 바꾸면 40~60대 사장님이 야외에서 못 읽습니다. [contrast checker](https://webaim.org/resources/contrastchecker/)로 꼭 확인해 주세요.

---

## 3. 이 앱 디자인의 전제

사용자는 **40~60대 소상공인 사장님**이고, 쓰는 상황은:

- 가게 안에서, **서서, 한 손으로**
- 조명이 나쁘거나 창가 역광
- 장사 중간에 끊겼다 다시 봄

그래서 일반 앱보다 의도적으로 **크게** 잡혀 있습니다.

| 항목 | 사릴스 | 흔한 앱 |
|---|---|---|
| 본문 글자 | 17 | 14~15 |
| 버튼 높이 | 58 | 44~48 |
| 최소 터치 영역 | 52 | 44 |

**이 값을 줄이자는 제안은 신중하게 해 주세요.** 화면이 허전해 보여도 이게 이 앱의 정체성입니다.

## 4. 시그니처 요소 — 태스크 스파인

`components/ProgressSpine.tsx`

이 앱의 핵심 주장은 **"영상 한 편이 아니라 짧은 촬영 여러 개"** 입니다.
그 구조를 계속 보여주는 세로 레일이 스파인이고, 촬영 흐름 전체에서 같은 형태로 반복됩니다.
카메라 화면에서는 가로 막대(`SpineStrip`)로 축약됩니다.

**디자인을 크게 바꾸더라도 이 요소는 유지하는 걸 권합니다.** 다른 숏폼 앱과 구분되는 유일한 지점입니다.

## 5. 색을 쓰는 규칙

| 토큰 | 언제 |
|---|---|
| `brand.600` | 주 행동 버튼. **한 화면에 하나만.** |
| `ink.900` | 제목, 본문 강조 |
| `ink.500` | 보조 설명 |
| `done.500` | 완료된 촬영, 잘 된 것 |
| `warn.500` | 다시 찍어야 함, 자료 부족 |
| `danger.500` | 삭제, 탈퇴 |

`brand` 색을 장식으로 여기저기 쓰면 "지금 눌러야 할 것"이 사라집니다.

## 6. 폰트

**Pretendard** (OFL 라이선스 — 상업적 사용 무료).
기능명세에 *"상업 이용 가능한 폰트만 사용한다"* 규칙이 있어서 이 폰트를 골랐습니다.
바꾸실 거면 **반드시 상업 사용 가능 여부를 먼저 확인**해 주세요. 영상 자막에도 같은 폰트가 들어갑니다.

파일 위치: `assets/fonts/`
필요한 파일 5개: `Pretendard-Regular.otf`, `-Medium`, `-SemiBold`, `-Bold`, `-Black`
(다운로드: https://github.com/orioncactus/pretendard)

## 7. 문구 쓰는 규칙

| 이렇게 | 이렇게 말고 |
|---|---|
| 이걸로 쓸게요 | 확인 |
| 다시 찍기 | 재촬영 |
| 찍을 순서 | 태스크 목록 |
| 올리기 | 게시하기 / 퍼블리시 |
| 반응 보기 | 성과 분석 / 인사이트 |

- 외래어와 업계 용어를 쓰지 않습니다. "포맷", "콘텐츠", "타깃"은 사장님 화면에 나오면 안 됩니다.
- 버튼 이름과 결과 문구를 맞춥니다. "올리기"를 눌렀으면 "올렸습니다"가 나와야 합니다.
- 오류 문구는 사과하지 않고, **뭐가 잘못됐고 뭘 하면 되는지**만 씁니다.

## 8. 피그마와 이 파일을 맞추는 법

피그마에서 **Variables**(변수)를 만들고 이름을 tokens.json 구조와 똑같이 지어 주세요.

```
피그마 변수 이름          →  tokens.json 위치
color/brand/600          →  color.brand.600
color/ink/900            →  color.ink.900
space/4                  →  space.4
radius/lg                →  radius.lg
```

이렇게 해 두면 개발자가 피그마 변수를 그대로 읽어서 이 파일을 자동으로 갱신할 수 있습니다.
(자세한 방법은 프로젝트 루트의 `사릴스_프론트엔드_개발문서.md` 3장을 보세요.)
